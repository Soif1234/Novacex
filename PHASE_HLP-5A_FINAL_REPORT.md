# PHASE HLP-5A: FINAL REPORT - CLOID MSGPACK SERIALIZATION PROVEN

## A. Exact Bug
The custom `HyperliquidMsgpackEncoder` in NovaCEX failed to correctly strip `undefined` properties from JavaScript objects during serialization. Specifically:
* `Object.keys(value)` iterated over all defined keys, including optional ones explicitly set to `undefined` (like `c: undefined` for `cloid`).
* Because Hyperliquid's canonical msgpack for L1 Actions strictly expects absent keys to be entirely omitted rather than explicitly encoded as `nil` (0xc0), this minor divergence drastically altered the byte sequence of the signed `Order` action payload.
* Due to the altered byte layout, `ecrecover` on Hyperliquid's backend produced a mismatched, pseudo-random agent wallet address (e.g., `0xa12...`), immediately causing an `INVALID_ORDER_PARAMETERS: User or API Wallet ... does not exist` error.

## B. Exact Code Change
In `src/services/liquidity/hyperliquid/hyperliquid.signer.ts` line 98:
**Before:**
```typescript
const keys = Object.keys(value);
```
**After:**
```typescript
const keys = Object.keys(value).filter(k => value[k] !== undefined);
```
This ensures strict adherence to the official SDK's omission pattern without rewriting the entire serialization schema or losing insertion order behavior.
